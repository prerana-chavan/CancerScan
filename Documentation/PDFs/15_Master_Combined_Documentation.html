3. Abstract

CancerScan is an AI-powered medical diagnostic tool designed to assist pathologists in analyzing lung tissue biopsy slides (Histopathology / H&E stained slides). The system uses a Deep Learning Convolutional Neural Network (CNN) to detect lung cancer and classify it into its specific subtypes (Adenocarcinoma vs. Squamous Cell Carcinoma). By automating the initial screening process, CancerScan reduces diagnostic time and provides a second layer of validation for medical professionals.

4. Problem Statement

Manual analysis of lung histopathology slides under a microscope is time-consuming, prone to human error, and suffers from inter-observer variability. Distinguishing between closely related lung cancer subtypes requires highly specialized expertise. There is a need for an automated, accessible, and highly accurate AI system to support pathologists in rural or understaffed hospitals.

5. Core Features

  1. Desktop Application: Secure, native desktop experience for doctors built with Electron and React.
  2. AI Inference: 3-class classification model using a custom MobileNet/CNN architecture.
  3. Automated Normalization: Macenko stain normalization standardizes slide colors before AI processing.
  4. H&E Gatekeeper: Prevents upload of non-medical images using pixel-level color validation.
  5. Secure Authentication: JWT-based login with bcrypt password hashing and RBAC.
  6. Report Generation: Automatic generation of downloadable PDF medical reports.
  7. Cloud Infrastructure: Global accessibility powered by Render and Neon.

05. ML Engine Documentation

The ML Engine is a dedicated Flask micro-service (api_server.py) on Port 5001.

The TensorFlow Model

  • File: models_lcscnet_full/lcscnet_fold1.h5 (~4.5 MB)
  • Output: 3-class probability array [Adenocarcinoma, Normal, Squamous Cell Carcinoma]

Inference Pipeline

Phase 1: H&E Gatekeeper

Analyzes RGB pixels to reject non-medical images with a 422 error.

Phase 2: Macenko Normalization

Standardizes stain colors. Resizes image to 224×224 pixels.

Phase 3: TensorFlow Inference

Outputs 3 probabilities. If confidence is below 55%, returns "Inconclusive — Manual Review Required".

SELECT id, patient_name, age, prediction_result, subtype, scan_date FROM patients ORDER BY scan_date DESC;

SELECT subtype, COUNT(*) as count FROM patients WHERE subtype != 'Normal / Benign Lung Tissue' GROUP BY subtype;

09. Authentication & Security Guide

1. Password Hashing (bcrypt)

hashed_password = bcrypt.hashpw(password.encode('utf-8'), bcrypt.gensalt()).decode('utf-8')

2. JSON Web Tokens (JWT)

token = jwt.encode({
    'user_id': user['id'],
    'role': user['role'],
    'exp': datetime.datetime.utcnow() + datetime.timedelta(hours=8)
}, settings.JWT_SECRET_KEY, algorithm="HS256")

3. Role-Based Access Control

Two roles: admin and doctor. Protected by @require_admin decorator.

4. Approval System

New registrations start with is_approved = 0. Admin must manually approve.

5. Brute Force Protection

5 failed attempts per minute from same IP → temporary block.

13. Viva Preparation Guide

Q1: Why Electron Desktop App instead of a website?
"Medical data is highly sensitive. A desktop app feels native and secure. It also allows future local GPU processing."
Q2: Why two separate ports/services?
"Microservices architecture. Decouples ML from DB operations. Prevents heavy inference from blocking routine queries."
Q3: Purpose of Macenko Normalization?
"Standardizes H&E stain colors across hospitals. Prevents CNN from learning color biases."
Q4: What if someone uploads a non-medical image?
"H&E Gatekeeper analyzes RGB distribution. Rejects non-tissue images with 422 error before TensorFlow sees it."
Q5: Why TensorFlow-CPU on Render?
"Render's free tier has no GPU. Full TensorFlow wastes 80MB RAM on CUDA libraries. CPU version prevents OOM crashes."
Q6: How are passwords secured?
"bcrypt with salt, 12 rounds. Even with database access, passwords cannot be reverse-engineered."
Q7: How are images stored in the database?
"Base64 encoded strings in a TEXT column. Images resized to 500px = ~75KB each. Self-contained, no S3 needed."

PostgreSQL Database (neondb)

Data Flow: Processing a Scan

  1. Doctor opens Electron app → "Analysis" screen
  2. Uploads slide image + patient details
  3. Axios sends POST to /api/analysis/predict with JWT
  4. @require_auth middleware verifies JWT
  5. Backend saves image temporarily, forwards to ML Engine
  6. Gatekeeper validates H&E staining
  7. Macenko normalizes colors
  8. TensorFlow returns 3-class probabilities
  9. Backend saves Base64 image + results to Neon DB
  10. Frontend displays result, enables PDF download
